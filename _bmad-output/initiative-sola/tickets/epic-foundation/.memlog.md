- (direction) Underlag: initiativets R1, R2, R3, R12, R13 (covers) och arkitekturryggraden (AD-1, AD-2, AD-3, AD-5, AD-20, Structural Seed); exempelapp Byggordning 1
- (decision) 2026-10-26 Pao: example/server i epik 1 är ett skelett (node:http, JSON, Problem Details, 404 not-found på okända /api/*); datalagret i minnet och seed-data kommer med första endpointen som läser dem i epic-providers, användare med lösenord i epic-login
- (decision) 2026-10-26 Pao: api.js skapas i epic-providers med sitt första anrop, inte som tom fil i epik 1; byggsteg 1 nämner bara index.html, app.js, style.css
- (decision) 2026-10-26 Pao: sola/sola.js är en tom modul; app.js gör import '#sola' och ett Node-test importerar #sola via package.json; första exporten kommer vid första utbrytningen (AD-4); ingen version-export
- (decision) 2026-10-26 Pao: proxyn skickar Host oförändrad så att servern i epic-login jämför Origin mot Host likadant i utveckling och drift (AD-7)
- (decision) 2026-10-26 Pao: sola dev --port med standard 3000; example/server läser PORT med standard 3001; båda exporterar en startfunktion som tar port 0 i tester och CLI:t är ett tunt skal
- (decision) 2026-10-26 Pao: tester ligger som *.test.js bredvid koden så att node --test utan argument hittar dem
- (decision) 2026-10-26 Pao: node --test kontrollerar CSP-header, hash och injicerad reload-klient; kontrollen i webbläsaren (CSP-fel, omladdning, CSS-byte) är ett manuellt steg för Pao i epikens avslutande verifiering, eftersom DOM-tester ligger utanför
- (decision) 2026-10-26 Pao: ingen spike; första storyn är den mest osäkra: sola dev serverar skalet under CSP med rätt hash
- (requirement) R1 (parent R1): en utvecklare startar exemplet med node example/server och node tools/sola.mjs dev example/web --mount /sola/=sola/ --api http://localhost:3001 och ser startsidans skal, utan installation
- (requirement) R2 (parent R2; AD-5): sola dev serverar roten på / och monterade kataloger på sina prefix, och svarar med roten/index.html på GET med Accept: text/html som inte matchar en fil
- (requirement) R3 (parent R2; AD-5, AD-7): sola dev proxar /api/* oförändrat till --api, inklusive Host, cookies och strömmande SSE; ett node --test mot en stubbe uppströms visar att Host, Cookie och Set-Cookie går igenom oförändrade och att en SSE-händelse når klienten innan svaret avslutas
- (requirement) R4 (parent R2; AD-5): en ändrad fil under roten eller en mount laddar om sidan och en ändrad CSS-fil byts utan omladdning, via en reload-klient som sola dev injicerar som extern modul under /__sola/; ingen fil i example/ känner till /__sola/
- (requirement) R5 (parent R3; AD-20): sola dev skickar CSP-headern i AD-20 med sha256 av import map-blocket i den HTML som serveras; ett node --test visar att hashen stämmer, och skalet visar inga CSP-fel i konsolen
- (requirement) R6 (parent R12; AD-3): sola/sola.js finns och appen når den via #sola, i webbläsaren genom import map i index.html och i Node genom imports i package.json
- (requirement) R7 (parent R13): node --test utan argument kör testerna för sola dev och example/server grönt, utan installation
- (requirement) R8 (parent R1; exempelapp Byggordning 1; AD-6): example/server svarar på okända /api/* med 404 application/problem+json och type /problems/not-found
- (constraint) Noll beroenden, inte heller devDependencies; inget byggsteg; endast Node >=24.12 (parent Constraints; AD-2)
- (constraint) sola dev är generisk: tools/ importerar aldrig från example/ och känner inte till appens routes; example/server serveras aldrig (AD-1, AD-5)
- (constraint) Inga HTML-sänkor och inga inline-skript eller inline-stilar utöver import map i sola/ och example/ (parent Constraints; AD-15, AD-20)
- (constraint) Engelska i kod, filnamn och sökvägar; kebab-case för filer (AD-11, Consistency Conventions)
- (constraint) sola dev och example/server exporterar var sin startfunktion som tar port 0; CLI:t är ett tunt skal; tester som *.test.js bredvid koden (beslut 2026-10-26)
- (constraint) Ingen lösning bryts ut till sola.js förrän den skrivs andra gången (parent Constraints; AD-4)
- (event) Self-validate pass 1 (koherens): godkänd; R1-R8 kontrollerbara med node --test eller Paos kontroll i webbläsaren, Boundaries har utanför-rader
- (event) Self-validate pass 2 (bevarande): godkänd; epikens tidigare Done when (djuplänk, proxy med cookies och SSE, reload, CSS-byte, inga beroenden, #sola, main) finns kvar i R2-R7 och Done when
